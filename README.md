# AlreadyUp

自然に起きて100歩歩いたこと、または期限直前の明示操作を確認できた場合だけ、その時刻のアラームを止める fail-safe 優先のアラームアプリです。

睡眠そのものは推定しません。歩数、通知、保存、取消処理に失敗した場合は「起きている」と判断せず、対象アラームを残します。

## 主な機能

- 最大10件のアラーム
- 「今日だけ」「毎日」「平日」「曜日指定」の繰り返し
- アラームごとのオン／オフと削除
- アラーム時刻の60分前から期限前までに、アプリを画面に表示したまま歩いた100歩による、対象周期だけの自動停止
- iPhone / Apple Watch の確認通知から「起きています」を押した周期だけの停止
- foreground でのループ音と、background での local notification 音
- 就寝時はアプリを画面に表示したまま充電する運用を正式手順とし、鳴動中と24時間以内にオンのアラームがある間は、アプリ表示中の画面を自動で消さない（下記「寝るときの手順」）
- 通知がオフ・通知音がオフ・状態を確認できない場合は、次のアラームを閉じられない警告に置き換え、`設定を開く` から端末の設定へ移動
- 既存の単一アラーム保存形式から複数アラーム形式への移行
- 「時刻」「繰り返し」を分けてレイアウトを動かさない追加モーダルと、一覧だけをスクロールする固定ホーム画面
- native wheel / clock dialを標準にし、時刻表示タップ時は時・分をキーボードから直接入力
- 追加・削除・失敗時の状態通知は閉じるボタンまたは上スワイプでdismiss。頻繁なオン／オフ成功時はbannerを出さない
- 上部summaryと操作層へ絞ったLiquid Glassと、追加フォーム／繰り返しの選択に追従してspring移動するglass lens
- iOS 26のnative Liquid Glass、旧iOS / WebのBlur、Androidの安定したfallback、Reduce Transparency / Reduce Motion対応
- 端末のローカル時刻に合わせ、同じ湖畔景観の実写寄りな朝・昼・夕・夜写真を連続cross-fadeする背景

## 時間帯に合わせた背景

背景は端末の現在時刻とtimezoneを使い、位置情報権限や外部APIなしで変化します。現在は日の出を06:00、日の入りを18:00とする基準モデルで、同一構図から生成・最適化した夜明け、昼、夕暮れ、夜のphotorealistic assetを時間帯keyframe間でcross-fadeします。codeで描いた星・太陽・月・山のillustrationは使用せず、描画時にmountする写真も隣接する最大2枚に限定します。

国籍は日の出・日の入りを決める情報ではないため使用しません。実際の地域・季節に合わせる場合は、位置情報を任意で許可した利用者だけ緯度・経度から日の出・日の入りを算出する追加機能として扱います。

## 動作ルール

| 入力・状態 | 判定 | 対象アラーム |
|---|---|---|
| アラーム時刻の60分前から期限前までに、アプリを画面に表示したまま100歩へ到達 | 起床確認 | その周期だけ停止 |
| 99歩以下 | 起床未確認 | 維持 |
| 60分前より前の歩数（前夜・日中など） | 数えない | 維持 |
| アプリを閉じている間・画面をロックしている間の歩数 | 数えない | 維持 |
| 期限直前の確認通知で「起きています」を押す | 起床確認 | その周期だけ停止 |
| 通知を閉じる、無応答、古い周期を操作 | 不明 | 維持 |
| センサー、保存、取消確認に失敗 | 不明 | 維持 |
| 期限と同時または期限後に確認 | 期限切れ | 維持 |

歩数はアラームの周期ごとに、アラーム時刻の60分前から数え直します。その周期の予約がそれより後に行われた場合は予約時刻から、同じ時間帯に別のアラームが歩数または確認操作で停止した場合はその停止時刻から数えます。前夜や日中の歩数、別のアラームを止めるのに使った歩数は数えないため、一度の100歩や確認操作が、別の時刻・別の日のアラームを止めることはありません。

60分前になるまでは歩数計を購読せず、次のアラームのカードに「起床確認は HH:MM から」と開始時刻を表示します。

数えるのは、アプリを画面に表示している間に歩いた分だけです。アプリを閉じている間や画面をロックしている間の歩数は、iPhone が記録していても数えません。トイレなどで歩いてから再び寝た場合に、誤ってアラームを止めないためです。アプリを画面へ戻すと、それまでに数えた歩数から続きを数えます。

## 繰り返しと通知予約

各アラームは、次の3周期を one-off local notification として個別に予約します。main alarm と起床確認通知を周期ごとに分けるため、最大件数は `10 alarms × 3 cycles × 2 notifications = 60 notifications` です。

この方式は iOS の保留 local notification 上限に収めつつ、周期ごとの安全な取消を可能にします。予約枠は次の時点で3周期まで補充します。補充はアプリが動いている間しかできません。

- アプリ起動時
- アプリへ戻るたび（`AppState` が `active` になった時）。通知が許可されている場合だけ行い、許可の確認画面は出しません。停止・オフの処理が終わっていないアラームは補充しません。
- アプリ内での起床確認・100歩の検知・アラーム停止の後

通知の「起きています」や通知からの停止だけで使い、アプリを開かない場合は補充されません。そのため繰り返しアラームの通知本文に「アプリを開くと次回以降の予約を続けます。」と添えています。先の周期がない「今日だけ」には添えません。

一覧の各アラームには、どこまで予約できているかを表示します。

| 状態 | 一覧の表示 |
|---|---|
| 予約が2周期以上残っている | `10/7(水)まで予約済み`（最後に予約した日付） |
| 繰り返しアラームの予約が残り1周期 | `10/5(月)まで予約済み・アプリを開くと先の分を予約します`（警告色） |
| 上と同じで、そのアラームの直近の補充が予約に失敗した、または停止・オフの処理が終わっていないため補充しなかった | `10/5(月)まで予約済み・先の分を予約できませんでした`（警告色） |
| オンなのに未来の予約がない | `予約がありません`（警告色） |
| オフ | `通知は予約されていません` |

「今日だけ」は1周期しか予約しないため、残り1周期でも警告しません。アプリを開いていても補充できなかったアラームに「アプリを開くと…」と表示しないよう、起動時・アプリへ戻った時・追加・オン・アプリ内での停止のたびに、アラームごとに直近の補充結果を記録しています。通知の許可・通知音に問題がある間は、この表示より通知の警告（次の節）を優先します。

> [!IMPORTANT]
> アプリを3周期以上まったく開かない（前面に戻さない）場合、その先の周期は補充されず、アラームは止まります。一覧の表示と通知本文でアプリを開くよう促すのは暫定対策です。本番リリース前には native/background の再予約方式を実装し、端末再起動・時刻変更を含む E2E 検証が必要です。

## 通知がオフのとき

アプリが画面に表示されていない間（閉じている・画面をロックしている・ほかのアプリを表示している間。background / terminated）にアラームを鳴らせるのは OS の local notification だけです。そのため、通知の許可状態を次のタイミングで `Notifications.getPermissionsAsync()` により確認し、鳴らない可能性がある間は「アラーム設定済み」に見える表示をしません。

- 起動時の読み込み完了後
- アプリへ戻るたび（`AppState` が `active` になった時）
- アラームの追加・オン/オフ操作の後（成功・失敗とも）

| 通知の状態 | 次のアラームの表示 | 一覧のオンのアラーム |
|---|---|---|
| 許可・通知音オン | 通常表示（時刻・残り時間・起床確認） | 予約の範囲（例: `10/7(水)まで予約済み`。前の節） |
| 未許可・拒否 | 「通知がオフです」「通知がオフのため、次のアラーム 10/3(土) 07:00 は、アプリを画面に表示したままにしていないと鳴りません。」 | `通知オフ・アプリ表示中のみ鳴ります` |
| 通知音オフ、または iOS の「目立たない配信」（provisional） | 「通知の音がオフです」「通知の音がオフのため、次のアラーム …は、アプリを画面に表示したままにしていないと音が出ません。」 | `通知音オフ・アプリ表示中のみ音が出ます` |
| 確認に失敗した・判別できない | 「通知の状態を確認できません」「…鳴るか確認できません。」 | `通知の状態を確認できません` |

- 警告は閉じられません。`設定を開く` から端末の設定（Expo Go で動かしている場合は Expo Go の設定画面）を開き、通知と通知音をオンにしてアプリへ戻ると、自動で通常表示に戻ります。
- 通知がオフでも、アラーム時刻にアプリが画面に表示されていれば端末内のループ音で鳴ります。ループ音が鳴り始められるのはアプリが画面に表示されている間だけで、その時刻にアプリを閉じている・画面をロックしている・ほかのアプリを表示していると鳴り始めません。そのため、アプリを閉じた場合に限らず「アプリを画面に表示したままにしていないと鳴りません」と表示します（「寝るときの手順」）。一度鳴り始めたループ音は、その後に画面をロックしたりほかのアプリへ切り替えたりしても鳴り続けるよう設定しています（`setAudioModeAsync` の `shouldPlayInBackground`。Expo Go では Expo Go 本体の background audio 設定に依存し、`app.json` の `enableBackgroundPlayback` は development build でのみ反映されます）。Expo Go 実機で鳴り続けるかは未確認です（[DESIGN の BED-08](docs/DESIGN.md)）。
- 通知がオフでも、保存済みのアラームと予約は解除しません。オンのアラームがない場合と、まだ一度も確認していない場合は警告しません。
- 消音スイッチ、音量、Focus、Android の通知チャンネル単位の音設定は検出できません（[docs/REMAINING_ISSUES.md](docs/REMAINING_ISSUES.md) の ALR-001 / ALR-003）。

## セットアップ

### 必要なもの

- Node.js 22 LTS（22.x の 22.13.0 以降）と npm を推奨します。任意の上位メジャーバージョンが対応するわけではありません。
- SDK 57 対応の Expo Go をインストールした iPhone（iOS 16.4 以降）
- iPhone と開発マシンが接続できるネットワーク
- Apple Watch 経由の確認を試す場合は、iPhone とペアリング済みの Watch

2026-09-05、実機の Expo Go が SDK 57 対応になったことを確認し、ユーザー承認のもと旧 SDK 54 固定を解除しました。このリポジトリは Expo SDK 57 を使用します。実装時は [Expo SDK 57 の versioned docs](https://docs.expo.dev/versions/v57.0.0/) を参照してください。

```sh
npm ci
npm start
```

別ネットワークから接続する場合は `npm start -- --tunnel --go` で起動してください。SDK 不一致のエラーは Tunnel や QR の作り直しだけでは解消しません。Expo Go とプロジェクトの SDK メジャーバージョンを合わせてください。

ターミナルの QR コードを iPhone のカメラまたは Expo Go で読み取ります。初回起動時は通知とモーションの権限を許可してください。

## 使い方

1. 右上の `＋` を押す。
2. 「時刻」で、iPhoneではwheel、Androidではclock dialから時刻を選ぶ。
3. 数字で直接指定したい場合だけ、表示時刻をタップして時・分を入力し、`この時刻に決定` を押す。
4. 「繰り返し」へ切り替え、「今日だけ」「毎日」「平日」「曜日指定」から鳴らす日を選ぶ。
5. `この内容で追加` を押す。
6. 一覧のスイッチでオン／オフを切り替える。不要な設定は `削除` から解除する。

「今日だけ」は現在より後の時刻だけ登録できます。時刻を過ぎた設定をもう一度使う場合は削除し、新しい時刻を登録してください。

## 寝るときの手順

2026-10-05、当面は「アプリを画面に表示したまま充電して寝る」ことを正式な手順にしました。アプリ内のループ音はアラーム時刻にアプリが画面に表示されていないと鳴り始めず、100歩の起床確認もアプリが画面に表示されている間しか動かないためです。

1. 寝る前に AlreadyUp を開き、アラーム一覧の画面を表示したままにする。
2. iPhone を充電器につなぐ（画面を点けたままにするため、電池を多く使います）。
3. 画面を手動でロックしたり、ほかのアプリへ切り替えたりしない。眩しい場合はコントロールセンターで画面の明るさを下げる。

アプリを表示している間は、鳴動中と、オンのアラームが24時間以内にある間（期限を過ぎて鳴る直前の周期を含む）は画面を自動で消しません（[Expo KeepAwake](https://docs.expo.dev/versions/v57.0.0/sdk/keep-awake/)）。アラーム時刻には止めるまでループ音が鳴り、60分前から100歩の起床確認を行います。オンのアラームが24時間より先にしかない場合や、すべてオフの場合は、端末の自動ロック設定どおりに画面が消えます。

> [!NOTE]
> この自動ロックへの復帰は、production の JS bundle で読み込んだ場合だけ起こります。`npm start`（`expo start` の開発モード）で読み込んだ場合は、Expo の開発用機能（`registerRootComponent` の `withDevTools`）がセッション中ずっと画面を点けたままにするため、アラームの有無にかかわらず画面は自動で消えません。確認方法は「開発時の検証」を参照してください。

アプリを閉じた場合や画面をロックした場合、アラームは OS の通知音が1回鳴るだけになり、ループ音も歩数による起床確認もありません。通知または通知音がオフの場合は、その1回の通知音も鳴りません（「通知がオフのとき」）。この違いは画面下部に「寝るときはアプリを画面に表示したまま充電してください」「画面ロック・アプリを閉じると通知音1回だけ・歩数確認なし」として常に表示し、アラーム追加画面の説明にも記載しています。この案内は一覧のスクロールの外に固定しているため、文字サイズや画面の大きさにかかわらず最初から見えます。通知がオフ・通知音がオフ・通知の状態を確認できない間は、鳴らない通知音を約束しないよう2行目を「画面ロック・アプリを閉じると鳴りません」「…音が出ません」「…鳴るか確認できません」に切り替えます。

画面を点けたままにする処理に失敗した場合は「画面を点けたままにできませんでした。…」と警告します。その場合は端末の自動ロックをオフにしてから寝てください。

本番は、アプリを閉じていても鳴り続ける自前ビルド（native alarm / AlarmKit など）へ移行する予定です（[docs/REMAINING_ISSUES.md](docs/REMAINING_ISSUES.md) の ALR-001）。

## Apple Watch で起床確認する

1. アラームをオンにする。
2. iPhone をロックする。
3. Apple Watch を装着し、ロック解除した状態で待つ。
4. 期限直前の確認通知で「起きています」を押す。
5. 対応する周期だけが停止されることを確認する。

iPhone がアンロックされている場合、通知は原則として Watch ではなく iPhone に表示されます。

## 開発時の検証

```sh
npm test
npm run typecheck
npx expo install --check
npx expo-doctor
npx expo export --platform all
```

Web export は UI と bundle の smoke test です。通知、Pedometer、Apple Watch 転送は実機で確認する必要があります。

### 画面スリープ防止（keep-awake）の実機確認

開発サーバーの dev bundle（`npm start` / `npx expo start`）では、Expo の `withDevTools` が開発用の tag（`ExpoKeepAwakeTag`）でセッション中ずっと画面を点けたままにします。アプリの条件で画面が消えるかどうかはこの状態では確認できないため、Expo Go で production の JS bundle を読み込んで確認します。

```sh
npx expo start --no-dev --minify
```

別ネットワークから接続する場合は `--tunnel --go` を追加します。QR を Expo Go で読み取り、一覧を表示したまま端末の自動ロック時間を過ぎるまで待ちます。24時間以内にオンのアラームがあれば画面が消えず、すべてオフにすると自動ロック設定どおりに消えることを確認します（[docs/DESIGN.md](docs/DESIGN.md) の BED-05）。

## 現在の重要な制約

- `Pedometer.watchStepCount` は background では更新されません。100歩のリアルタイム確認は foreground が前提です。
- 歩数監視の範囲は2026-10-05に「アラーム時刻の60分前から期限まで、アプリを画面に表示している間だけ」と決定しました。数えるのは `Pedometer.watchStepCount` がアプリ表示中に観測した歩数と、同じ窓で保存済みの歩数だけです。iOS の歩数履歴（`Pedometer.getStepCountAsync`）は合算しません。アプリが背面へ移ると購読を止め、前面へ戻ると保存済みの歩数から続きを数えます。アプリを開かないまま期限を迎えた場合は起床を確認できないため、アラームが鳴ります。
- 通常の local notification は、消音、音量、Focus、通知権限、OS の配送判断に影響されます。通知権限と通知音の設定は起動時とアプリへ戻るたびに確認して画面に表示しますが、消音スイッチ・音量・Focus は検出できません。音が必ず鳴る保証はありません。
- ループ音を鳴らし始められるのは、アラーム時刻にアプリが画面に表示され JavaScript が動いている間だけです（鳴り始めた後は background でも鳴り続けるよう設定していますが、Expo Go 実機では未確認です。DESIGN の BED-08）。その時刻にアプリが background / terminated の場合は通知音に依存します。そのため当面は「アプリを画面に表示したまま充電して寝る」ことを正式手順とし、アプリ表示中は画面を自動で消さないようにしています（「寝るときの手順」）。画面を手動でロックした場合、ほかのアプリへ切り替えた場合、着信などでアプリが中断された場合は防げません。
- 通知アクションを押した時に JavaScript 実行環境が終了している場合、取消処理が走らずアラームが鳴る可能性があります。これは安全側の失敗ですが、UX として未解決です。
- アプリを開かない間の先3周期を越える予約補充（現在はアプリ起動時と前面へ戻った時だけ補充）、端末再起動、timezone / 手動時刻変更との整合は本番リリース前の gate です。
- Expo Go は開発確認用です。App Store / Google Play 配布では development build と native alarm 能力を含む別の配布設計が必要です。
- iOS / Android のアプリ識別子は現在 `app.alreadyup.prototype` のままです。既存インストールとの同一性や署名に影響するため、本番識別子は人間承認後に変更します。`APP_VARIANT=production` の設定機構と所有者待ちの項目は [docs/RELEASE_PROFILES.md](docs/RELEASE_PROFILES.md) を参照してください。

詳細な契約と状態遷移は [docs/DESIGN.md](docs/DESIGN.md)、本番リリースまでの残項目は [docs/REMAINING_ISSUES.md](docs/REMAINING_ISSUES.md) を参照してください。
