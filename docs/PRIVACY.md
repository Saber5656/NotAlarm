# AlreadyUp データとプライバシー

この文書は ALR-011 の収集項目・目的・保存先・保持・削除を、現在のコードに基づいて記録する。法的助言ではなく、各国のストア審査・法令への適合を保証しない。公開用のプライバシーポリシー URL は未作成であり、この文書を公開 URL として扱わない（ストア提出物は ALR-016 で別に確定する）。アプリ内の説明は `src/localDataDeletion.ts` の `LOCAL_DATA_COPY` で、この文書と食い違わないよう同時に更新する。

## 保存する項目

すべてこの端末の `AsyncStorage`（アプリのローカル保存領域）に保存する。サーバーやアカウントは使わない。

| 項目 | 内容 | 目的 | キー |
| --- | --- | --- | --- |
| アラーム定義 | 時刻、繰り返し、オン/オフ、作成時刻、各周期の期限・状態（`armed` / `ringing` など）、歩数（100歩判定用の件数）、起床確認の時刻と種類、予約した通知の識別子 | 鳴動・停止・補充・復旧 | `already-up/alarm-definitions/v2` |
| 旧形式の単一アラーム | v1 からの移行元。移行後は消える | 移行 | `already-up/active-alarm/v1` |
| 停止の復旧記録 | 取り消し途中のアラームと周期 ID | 停止・無効化の再試行 | `already-up/alarm-cancellation-journal/v1` |
| 抑止の復旧記録 | 起床確認で止めた周期と通知識別子 | 取り消し結果が不明な停止の復旧 | `already-up/suppression-journal/v1` |
| 削除の意図 | 削除前に読み取った通知識別子と要求時刻 | 削除が途中で止まったときの再開 | `already-up/storage-reset-intent/v1` |
| 判別不能な通知の注意 | フラグのみ（識別子なし） | 解除できなかった通知を警告し続ける | `already-up/storage-reset-limitation/v1` |
| 背景の日の出設定（任意） | 固定／地域ID／現在地モードでは0.1度（約11km）に丸めた緯度経度・端末のタイムゾーン・保存時刻。未設定なら保存しない | 背景の明暗の切替時刻 | `already-up/sun-preference/v1` |

利用者設定（音・振動など）、アカウント、連絡先、広告 ID、分析用 ID、診断ログは保存しない（現在そうした機能はない）。

## 保存しないもの

- 加速度・ジャイロなどの生の動きデータ。歩数は OS の歩数計（`expo-sensors` の `Pedometer`）が返す「歩数の増分」だけを使い、その合計を周期ごとに保存する。取得は**アプリを画面に表示している間**に限る。
- HealthKit / ヘルスケアのデータ。現在連携しない（ALR-012 は評価課題）。
- 睡眠の推定結果。

## 位置情報（任意の日の出・日の入り背景、ALR-017）

- 既定では位置情報を使わない。権限は起動時にも設定画面を開いたときにも要求しない。背景は固定の6:00／18:00のまま、従来と同じ見た目になる。
- 「地域を選ぶ」は内蔵の座標表だけを使い、権限もネットワークも不要。
- 「現在地を使う」ボタンを押した場合だけ、前景で一度、最も粗い精度（`Accuracy.Lowest`、約3km）で位置を取得する。バックグラウンド位置、継続追跡、サーバー送信、住所検索は行わない。10秒で打ち切り、失敗時は固定の時刻のままにする。
- 端末に残すのは、緯度経度を0.1度（約11km）に丸めた値、端末のタイムゾーン、保存時刻だけ。取得した生の座標と移動履歴は保存しない。
- 「固定の時刻」を選ぶと保存した位置は消える。「データを削除」でも消える（`ALARM_STORAGE_KEYS`）。
- 位置情報の許可が取り消された、端末のタイムゾーンが変わった、保存内容が読めない、白夜・極夜で日の出がない場合は、固定の時刻に戻して理由を短く表示する。
- この設定は背景の明るさにだけ使う。アラームの時刻・予約・鳴動・停止は背景や位置情報に依存しない。
- 日の出・日の入りは端末内で計算し（`suncalc`）、ネットワークを使わない。
- 削除との関係: 削除を確定した時点で、取得中の位置情報の問い合わせ・読み込み・保存を直ちに無効化する。保存はアラームと同じ排他制御と削除ゲートの内側で行うため、削除中や途中で止まっている間は書き込まず、遅れて届いた権限の回答や位置で削除済みのデータが復活したり背景が変わったりしない。削除が完了するとメモリ上の設定も固定に戻す。途中で止まった間は設定の変更と位置情報の許可操作を無効にし、「データを削除」の再実行で続行できる。
- 位置情報の許可の取得と実機での挙動は未確認（`docs/DEVICE_TEST.md`）。

## 通知

予約通知は端末の OS が保持する。本文は固定文言で、歩数や個人情報は入れない。通知データにはアラーム ID・周期 ID と、このアプリの所有を示す識別子が入る。通知の予約・配送はすべて端末内で完結し、このアプリがサーバーへ送ることはない。

## 保持期間

- アラーム定義: 利用者が削除するか、設定シートの「データを削除」を実行するまで保持する。完了・停止した周期は次回の補充で置き換わる。自動で期限切れにはしない。
- 復旧記録: 対応する停止・抑止が完了した時点で消える。完了できない間は残る。
- 診断ログは取らないため、保持するログはない。ログがなくても fail-safe 判定は動作する。

## 外部への通信

- このアプリは、保存したアラームや歩数、起床確認の時刻を外部へ送信しない。コード上にそのための通信処理はない。
- **ただし Expo の開発環境は別である。** Expo Go や開発サーバー（`expo start`）で動かしている間は、アプリの JavaScript や素材を開発ホストから読み込むため、同じネットワーク上で通信が発生する。Expo Go や OS、Expo のサービスが独自に収集するデータは、このアプリの管理外であり、この文書は保証しない。「完全にオフライン」「通信しない」とは言えない。
- 配布ビルド（本番識別子）は未確定で、通信の実測も未実施である。

## 削除

設定（ヘッダー「⋯」）の「データを削除」は、2回の確認後に次の順で行う（`src/storageReset.ts` の `createStorageResetService`）。

1. 削除の意図（読み取れた通知識別子）を保存する。
2. このアプリのものと確認できる予約通知だけを識別子で解除する。他のアプリの通知は解除しない。全体のキューは消さない。
3. 解除を再確認できたときだけ、上表の保存データを順に消し、最後に意図を消す。解除を確認できなければ保存データは消さず意図を残す。ただし通知の一部はすでに解除済みで、キーの削除も途中で失敗しうるため、**失敗時に「何も変わらない」とは言えない**。一部が消えた状態で意図が残り、再実行すると意図に残した識別子から続きを行う。
4. このアプリのものか判別できない古い形式の通知は解除せず、残っていることを警告する。

追加の性質:

- 他の保存・停止・補充と同じ排他制御の中で実行する。
- 鳴動中は開始できない。鳴動が始まったら設定シートは閉じ、停止ボタンを優先する。
- 失敗しても画面上のアラームと鳴動中の周期は書き換えない。自動では再実行せず、利用者の再操作か、再起動後の復旧カードからのみ続行する。
- 削除の意図が残っている間は、保存層（`src/storageResetGate.ts`）が、ロックの中で実際の操作の直前に、定義・停止記録・抑止記録・旧形式からの移行の書き込みと、その中で行う通知の予約を拒否する。画面側の無効化には依存しないため、古い確認ダイアログや実行中の補充も止まる。起動時の復旧・補充、前面復帰の補充、新規追加、アラームの削除・オン/オフ、期限到達の更新、歩数の保存が対象。
- 鳴動中の停止は、音の停止と通知の消去までは行う（保存の失敗を理由に鳴らし続けない）。ただし保存は拒否されるため、記録は更新せず、古いアラームを書き戻すこともない。画面には、削除の再実行が必要な旨を表示する。
- 削除が完了した時点で世代を進め、完了前に読み取った結果（実行中だった補充など）は画面に反映しない。画面側の警告済みの記憶も消す。
- 保存データを読めない場合の既存のリセット（復旧カード）も同じサービスを使う。
- 利用者向けの書き出し（export）は実装しない。

## 将来の保存先を追加するときの統合要件

削除サービスは、保存キーの一覧（`ALARM_STORAGE_KEYS`）と、通知識別子の読み取り（`readOwnedIds`）で対象を決めている。次の変更を統合する担当は、**同じ変更の中で**両方へ追加し、削除テストへ該当キーを足す。

- Issue #15 の編集ジャーナル
- Issue #13 の孤児（orphan）ジャーナル
- 設定の保存（言語など。背景の日の出設定は反映済み）。これらは通知識別子を持たなくても、キーだけは削除対象に含める。

追加を忘れると「データを削除」後に旧データや再開すべき記録が残る。これは自動検出できないため、新しい `already-up/` キーを導入するレビューで確認する。
